comm_agent 3GPP Rel-15 NR协议中关于LDPC Base Graph 1/2的选取准则、提升集定义及速率匹配机制的具体规范是什么？
### 3GPP Rel-15 NR协议中LDPC Base Graph 1/2选取准则、提升集定义及速率匹配机制的规范 **专业结论：** 在3GPP NR（Release 15及后续版本）协议（TS 38.212）中，LDPC码采用双Base Graph（BG1和BG2）结构以兼顾大码块的高吞吐与小码块的低开销。其选取严格基于传输块（TB）的载荷大小（$A$）与调制编码策略指示的码率（$R$）；提升集（Lifting Size, $Z_c$）由8组特定的离散值构成以适配不同码长需求；速率匹配机制则依托环形缓冲区（Circular Buffer）及冗余版本（RV）起始位置的选择来实现高效的HARQ重传。 #### 1. LDPC Base Graph 1/2 的选取准则 根据 **TS 38.212 Clause 5.2.2 (或6.2.2/7.2.2)** 的规范，在TB初始传输及后续重传时，各码块（Code Block）的编码方式选取规则如下（$A$为包含CRC的载荷大小）： - **使用 LDPC Base Graph 2**：若满足以下**任一**条件： - $A \le 292$ - $A \le 3824$ 且 $R \le 0.67$ - $R \le 0.25$ - **使用 LDPC Base Graph 1**：若不满足上述任何条件（即用于大码块、高码率场景，$A > 3824$ 且 $R > 0.67$，或 $292 < A \le 3824$ 且 $0.25 < R \le 0.67$）。 *注：BG1的最大码块大小为8448比特，BG2为3840比特。* #### 2. 提升集（Lifting Size）定义 LDPC码的奇偶校验矩阵是通过将Base Graph中的节点替换为 $Z_c \times Z_c$ 的循环置换矩阵得到的。根据 **TS 38.212 Table 5.3.2-1**，提升集大小 $Z_c$ 被划分为8个集合（Set index $i_{LS} = 0 \sim 7$），共定义了50多个离散的提升值，以提供精细的码长适配： - **Set 0**: $\{2, 4, 8, 16, 32, 64, 128, 256\}$ （2的幂次） - **Set 1**: $\{3, 6, 12, 24, 48, 96, 192, 384\}$ （3的倍数） - **Set 2**: $\{5, 10, 20, 40, 80, 160, 320\}$ （5的倍数） - 依此类推，分别基于质数7、9、11、13、15构建相应的序列。 选取 $Z_c$ 时，系统会在包含所需 $Z_c$ 的集合中寻找满足 $K_b \cdot Z_c \ge K'$ 的最小 $Z_c$ 值。 #### 3. 速率匹配机制（Rate Matching） 速率匹配旨在将编码后的比特流映射到物理层分配的资源上，具体规范见 **TS 38.212 Clause 5.4.2**： - **环形缓冲区映射**：编码输出序列 $d_0, d_1, \dots, d_{N-1}$ 首先被写入长度为 $N_b$ 的环形缓冲区（Circular Buffer）。 - **比特选择与交织**：系统根据冗余版本号（$rv_{id} = 0, 1, 2, 3$）确定从环形缓冲区读取的起始位置 $k_0$（定义于 **Table 5.4.2.1-2**）。 - 例如对于BG1：$k_0$ 分别对应 $0$、$\approx 0.25 N_{cb}$、$0.5 N_{cb}$ 和 $\approx 0.84 N_{cb}$ 的不同位置偏移。 - **输出序列生成**：从起始位置 $k_0$ 开始，按顺序在环形缓冲区中循环读取 $E$ 个有效比特（跳过标记为NULL的填充比特），形成最终传输序列 $e_0, e_1, \dots, e_{E-1}$。此机制通过打孔（Puncturing）和缩短（Shortening）灵活支持了广泛的码率需求。 **资料缺口补充说明：** 前期调研资料指出文献未覆盖协议级细节，本次基于3GPP TS 38.212官方标准填补了上述空白。针对Wiesmayr等(2024)提到的速率匹配打孔模式优化对少量迭代解码性能的影响，上述标准中的RV起始位置与比特选取逻辑即为其在标准层面的底层实现依据。

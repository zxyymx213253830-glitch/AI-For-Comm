OpenTrek 能力增强点（基于 PDF 文档）
1. SSE 流式实时输出
OpenTrek 的 /run 接口支持 SSE 流式返回，将 思考过程（thought.delta）和回答文本（message.delta）分离输出。这天然契合项目"全链路日志"的铁律——思考过程可独立记录和展示，回答文本拼接后输出用户。
来源：发起agent调用.pdf — SSE 流式输出格式（object: thought.delta / message.delta）
2. 原生 Trace 支持
/run 接口支持 trace=true 参数，OpenTrek 原生返回调用链路记录。无需额外开发即可实现"全过程可追溯"的答辩要点，比百炼平台的日志方案更轻量。
来源：发起agent调用.pdf — trace 参数（当 trace=true，控制是否返回 trace 记录）
3. 知识库高级检索（AND/OR 复合逻辑）
OpenTrek kortex API 支持 advancedRules 参数，可按文件名（fileName）进行 EQ（等于）、IN（包含）、IS_NOT_NULL（非空）、LIKE（模糊匹配）等复合逻辑过滤。适用于精确定位"3GPP TS 29.274 中的 GTPv2 Create Session"等场景，比百炼的简单向量检索更灵活。
来源：知识库检索.pdf — advancedRules 参数（operator: AND/OR, conditions: simple/nested）
4. 用户级记忆隔离（memoryUserId）
createSession 接口支持可选参数 memoryUserId，按用户标识生成隔离的记忆分区。在多 Agent 协作场景下，每个 Agent 节点可维护独立的用户记忆上下文，无需自行管理记忆存储。
来源：创建session.pdf — memoryUserId 参数（用于区分用户的标识，与平台用户 ID 无关）

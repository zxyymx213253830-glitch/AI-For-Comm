## 三、关键发现

### 3.1 "2 万多秒"记录已精确定位 ✅

**Trace `b0e45fd0`（requestId `0d9204ad`，08-06 22:07:28，版本 1786024250191）**：

| Span | 状态 | 耗时 | 说明 |
|------|------|------|------|
| 开始 | 成功 | 33ms | — |
| 任务规划套件 | 成功 | 82.6s | — |
| 任务规划套件-LLM | **失败** | 82.4s | `error.code=10041`，`error.message="无规划任务结果"` |
| **结果渲染任务** | 成功 | **24612.0s ≈ 6.84 小时** | 22:08:51 → **次日 04:59:03** |

> **这就是用户说的"跑了 2 万多秒"的记录**（24611956ms）。

另有 08-05 23:16:26 的记录（e49f41ed）结果渲染任务挂起 **6097.4s**。

**模式**：LLM 节点失败（10041）→ 结果渲染任务（endEvent）后台挂起数小时。

### 3.2 "空回复"根因：三层问题叠加

#### 层 1：模型输出格式不被"任务规划套件"接受 → 10041

- 0d9204ad：LLM 实际生成了 **4365 tokens 的完整 Verilog**（runtimeData 有完整代码），但平台报 `10041 无规划任务结果`
- 原因：模型输出 ```verilog 代码块，而平台要求 JSON 格式（`{"action":"fr","actionName":"最终结果输出","actionParam":{"content":"..."}}`）

#### 层 2：即使格式正确，"结果渲染任务"也会丢内容/截断

| 测试 | LLM 输出 | 结果渲染输出 |
|------|----------|--------------|
| 第 2 次（a5f08c37） | 2190 字符 JSON，content 含完整代码 | **null（空回复！）** |
| 第 3 次（5bf359a0） | 1773 字符 JSON，content 含完整代码 | **仅 112 字符**（截断） |

#### 层 3：80s 流式推送超时

- 模型生成完整代码需 82~115s，超过平台 80s 推送上限
- 客户端收到 `IbpStreamReceiveTimeoutException`，后台继续跑

### 3.3 与 math_agent 对比 → 找到关键差异

**math_agent 能正确输出 936 字符**，对比其 LLM span 输出格式：

```
math_agent: "result" = "Action:\n```json\n{...}\n```"   ← 带 `Action:` 前缀 ✅
hw_agent:   "result" = "```json\n{...}\n```"            ← 无前缀 ❌
```

**关键差异**：`Action:` 前缀！math_agent 有，hw_agent 没有。这很可能是渲染任务正确解析的关键。

### 3.4 其他发现

- **模型已切换**：当前版本（1786025538444）实际执行模型是 **qwen3.6-plus**（旧版本为 deepseek-v4-pro）
- **渲染任务挂起是平台级现象**：math_agent 的渲染任务也挂起 23965s（6.65 小时），但不影响输出内容
- **trace 详情页 undefined**：渲染任务挂起期间 span 数据未落库

## 四、改进方案

### 4.1 Prompt 改进设计

基于对比分析，改进后的 Prompt 需要：

1. **明确要求 `Action:\n```json\n` 前缀**（与 math_agent 一致）
2. **明确要求 content 是纯文本**（不要用 ```verilog 包裹）
3. **要求代码紧凑**（减少长度，避免 80s 超时）

改进后的 Prompt 模板：

```markdown
# 你的角色
硬件实践 Agent

你是 FPGA/Verilog 工程师。精通同步/异步 FIFO、状态机、AXI/UART/SPI。

## 输出格式（最重要）

**必须严格按以下 JSON 格式输出，不要有任何其他内容：**

Action:
```json
{
  "action": "fr",
  "actionName": "最终结果输出",
  "thought": "简要说明设计思路",
  "actionParam": {
    "status": "success",
    "content": "完整的 Verilog 代码（纯文本，不要用 ```verilog 包裹）"
  }
}
```

## 代码规范

- 时序逻辑：非阻塞赋值 `<=`
- 组合逻辑：阻塞赋值 `=`
- 复位：`rst_n` 低有效
- 时钟：`clk`
- 代码要紧凑，减少空行和注释

## 禁止

- 不要在 content 里用 ```verilog 或 ``` 包裹代码
- 不要寒暄（"好的，我来写..."）
- 不要在 JSON 外输出任何其他内容
- 不要占位符（`// TODO`）

## 协作

完成后发送给 verify_agent。收到【不通过】时，重新输出完整代码。
```

## 七、结论

- **本地代码无问题**：`createSession → /run` 调用链正常
- **空回复根因在平台**：① 任务规划套件格式校验问题（10041）；② 结果渲染任务渲染 bug（null/截断）；③ LLM 失败后渲染任务后台挂起数小时；④ 80s 流式推送超时
- **改进方向**：Prompt 里要求模型输出带 `Action:` 前缀的 JSON 格式（与 math_agent 一致），content 纯文本不带代码块包裹

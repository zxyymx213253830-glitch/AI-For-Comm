# 平台 demo 展示文稿

**展示口径**：只演 OpenTrek 平台上的真实资产（智能体、知识库、技能、工具、会话留痕）；科研任务耗时 30 分钟量级，现场不跑，**直接展示已产出的成品报告 HTML**。全程约 10 分钟。

---

## 零、开场前检查（提前 10 分钟做）

| # | 检查项 | 达标标准 |
| :---: | --- | --- |
| 1 | 平台可访问 | 浏览器打开 `http://<platform-host>:30226/` 能登录，工作空间显示「AI For Comm」 |
| 2 | 本地服务在跑 | `python web\app.py` 已启动（`main.py` 只能进控制台交互，不起 Web），`http://127.0.0.1:7860/` 能打开首页 |
| 3 | 成品报告就位 | 打开 `最终提交材料\演示成果\` 确认报告 HTML 能正常显示（**不依赖网络**） |
| 4 | 分页材料 | 汇报书 PDF 打在手上（23 页），万一投屏故障可口头讲 |
| 5 | 关掉杂项 | 关闭无关标签页、微信、命令行窗口（避免露密码） |

> 网络不通时的兜底：平台若访问不了，直接切到本地 Web 的设置页（`/settings`），那里是平台配置的镜像，同样能讲完第 2~5 段。

## 二、逐段操作与讲稿

### 第 1 段 · 定位（40 秒）

**操作**：登录后停在平台工作台，只显示工作空间名和左侧菜单。

**讲稿**：
> 我们做的是「AI For Comm」——一个面向通信工程科研的多智能体协作平台，建在这个内网的 OpenTrek 智能体工厂上。一句话概括它干什么：**把一个通信课题，自动变成一份可以拿去评审的研究报告**。台上是 7 个分工明确的智能体和它们的资料库，台下是我们自己写的一层编排和工具。整个系统最核心的主张是八个字：**能算的绝不让它猜**。

### 第 2 段 · 七个智能体（2 分 20 秒，每个约 20 秒）

**操作**：进「智能体」列表 → 逐个点开，展示提示词/角色设定页 → 退回列表。顺序按下面走，不要乱序。

**讲稿（逐个）**：
> **总体规划智能体 comm_agent**：它是默认牵头人，负责把课题拆成子问题、派给专家，同时是通信协议领域的专家——3GPP 协议解读、链路预算、组网分析归它管。
>
> **math_agent 数学专家**：负责信息论和推导。它的特殊之处是**不信它手算**：要求它把推导写成 SymPy 代码，由本地引擎执行并复核。
>
> **hw_agent 硬件专家**：FPGA 和 Verilog 方向，代码交付标准是"进过 Keil 实际编译"，还配了本地多版本工具链。
>
> **sim_agent 仿真专家**：蒙特卡洛仿真、误码率曲线。它是本地工具用得最重的一个：先出方案、本地真跑、再出可复现代码，最后交结构化的数据回执。
>
> **lit_review_agent 文献调研**：负责查资料。它有两条腿——公网检索加平台知识库，每篇文献必须标可信度等级，禁止编造。
>
> **verify_agent 校验**：这是我们的质检岗，专职挑毛病，输出结构化结论：通过还是存疑、问题清单、修改建议。**它的权限是被设计出来的，不参与研究。**
>
> **report_agent 报告**：只负责把材料编排成稿，平台约束写死了"不要原创、不要改数字、不要补公式"。
>
> 每个智能体都是独立版本化的资产，改提示词走"草稿—评测—上线—锁定"，线上有主智能体兜着，不会越改越坏。

### 第 3 段 · 五个知识库（1 分 20 秒）

**操作**：进「知识库」→ 点开一个看条目列表 → 退回，指一下检索配置页。

**讲稿**：
> 知识库按领域分了 5 个，各自绑定到对应智能体：通信协议、香农与排队论公式、仿真模板、硬件开发指引、校验标准。
>
> 关键设计是**每个库的检索参数是分别调过的**，不是一套默认值通吃。比如公式库查的是符号和别名，所以 Top-K 只取 2、相似度门槛压到 0.05，宁缺毋滥；协议库查的是整段规程，所以取 8 条、门槛放到 0.18 保召回；硬件库要看到完整代码，所以把结果数上限放到 8000 字符。
>
> 这五个库总共沉淀了 24 条经过校验的知识，入库前都跑过真实检索验证。

### 第 4 段 · 技能中心（1 分钟）

**操作**：进「技能中心 / Skills Hub」→ 展示 3 个技能 → 点开一个看内容。

**讲稿**：
> 技能是把方法经验打包成 ZIP 上传到平台的，现在上面有三个：报告审美规范、报告章节汇编、仿真五步法。
>
> 这一块的实测结论比资产本身更值得说：技能上传、版本发布、共享这条链路我们是打通并验证过的；但**角色对话型的智能体不支持挂载空间技能**——这个能力只有工作流型智能体有。所以我们没有为了"有技能"而造工作流智能体，而是把技能内容直接内联进了智能体提示词，效果等价、链路更短。**平台做不到的事，我们不假装做到了。**

### 第 5 段 · 工具中心（1 分 20 秒）

**操作**：进「工具中心」→ 看 4 个 API 工具 → 点开任一智能体详情页，指出工具挂在它身上。

**讲稿**：
> 工具中心上注册了 4 个 API 工具，搭载到对应智能体：数学专家挂了公式校验和符号求解，仿真专家挂了信道模型和误码率计算，协议专家挂了协议查询。
>
> 但要跟各位说清楚一个实测结论：**平台自带的工具插件类型不支持本地自定义类型**，所以真正在跑的数值计算，是在我们本地的工具层执行的——SymPy 推演、通信算法库、Python 沙箱、Verilog 编译仿真。平台侧的工具是能力声明与编排入口，本地侧才是真算真跑的手脚。这个分工是平台的限制决定的，不是我们偷懒。

### 第 6 段 · 会话与调用留痕（1 分 20 秒）

**操作**：打开一次历史会话（或调用记录页），展示思考链、检索片段、工具调用轨迹；往下翻几条。

**讲稿**：
> 这是真实调用的留痕。平台只给了 3 个接口——创建会话、调用、订阅流，所以我们的会话管理完全自己实现：**本地 UUID 加会话重建**，不依赖平台保存状态，也方便审计。
>
> 每一次调用的请求、响应、重试、耗时都落盘到日志，报告里每个结论后面那个"展开专家原文"，点开就是这里的原始片段，中间没有人工改写。
>
> 稳定性上做了三件事：连续空回复会自动重建会话重试；平台调用有 180 秒硬超时，所以长文本统稿走分段；文献检索被限流时有冷却和知识库兜底。**这些不是设计亮点，是在内网真跑必然要踩的坑。**

### 第 7 段 · 成品报告（2 分 40 秒，重头戏）

**操作**：切到成品报告 HTML（本地文件双击打开，或报告库页里点进）。按下面顺序滚动，**不要一次滚到底**。

1. 停在封面：标题、课题、评级徽章、六维雷达/评分
2. 滚到协作链路图：六个节点、耗时
3. 滚到"核心发现"：点开一个折叠块，露出专家原文
4. 滚到交叉分析与校验意见
5. 滚到仿真图（如果这份报告有图）
6. 最后滚到附录：调用清单、留痕编号

**讲稿**：
> 这是平台端到端产出的研究报告，全流程无人工干预。它的结构是固定的：封面给评级，正文按"综述—核心发现—交叉分析—校验意见—结论—方法"六段走。
>
> 三个地方值得看。**第一，协作链路图**：谁参与了、各自花了多久、系统总耗时，一目了然，这是从调用日志生成的，不是画的。**第二，每个结论都可溯源**：点"展开专家原文"，看到的就是那个智能体当时输出的原话，包括它引用的文献编号和公式。**第三，报告里带着反对意见**：校验专家判"存疑"的条目、分歧点、缺口清单，原文照录，不粉饰。
>
> （指着仿真图）这张误码率曲线是本地真跑出来的：10^6 比特蒙特卡洛，和理论值同图对比，图上标了最大偏差。不是示意图。
>
> （指着附录）最后是留痕清单：调用了哪些智能体、哪个版本、耗时多少、日志编号是什么。**任何一条结论，按这个编号都能倒查回原始调用。**

### 第 8 段 · 数据与收尾（40 秒）

**操作**：切回本地 Web 报告库首页，指一下报告总数和评级分布。

**讲稿**：
> 现在库里有 7 份这样的报告，覆盖从香农公式推导到 PUSCH 频域均衡、Massive MIMO 的完整课题。质量上我们做过两轮量化评测：专家互评 37 项检查得分 35，智能体互评 18 项满分；多智能体端到端跑批的自动化校验正在进行，结果以附录复核索引为准，未验证的数字我们不写。
>
> 收尾一句：这套系统最有价值的不是"能生成报告"，而是**报告里的每个数字都可以被追问到底**——它敢把校验专家的批评原文印在自己身上。谢谢。

## 三、评委可能追问与应答口径

| 追问 | 怎么答 |
| --- | --- |
| 这和直接用聊天机器人有什么区别？ | 三点：分工路由加知识库接地；数学结论由本地 SymPy 复核而不是模型手算；独立校验专家加报告内留痕，结论可倒查。 |
| 报告是自动生成的，那正确性谁负责？ | 六道质量门：接地→计算接地→约束→评审→校验→编译。校验是独立岗位，判"存疑"不通过会标注但不阻塞发布，**把不确定性如实呈现比假装全对更重要**。 |
| 跑一次要多久？ | 3 到 30 分钟，取决于课题复杂度和专家数量；最慢环节是文献调研。现场不跑，展示的是已产出成品。 |
| 为什么有些功能没做？ | 三条硬约束：内网无公网依赖、平台只有 3 个调用接口、用户交互必须非命令行。凡超出这三条的能力，我们只做可行性评估，不落地。 |
| 数字能不能核实？ | 汇报书附录 B 有复核索引，每个数字对应的仓库路径和命令都列着，会后欢迎抽查。 |

## 四、节奏提示（给自己看）

- 第 2 段最容易超时：7 个智能体各 20 秒，**别展开技术细节**，细节留给第 6、7 段。
- 遇到点不开、加载慢：**立刻讲话过渡**（"这个页面加载需要几秒，我先说下一个"），不要当场等。
- 报告展示是加分项，宁可压缩前面也要保住第 7 段的 2 分 40 秒。
- 全程不要说"AI 帮我们写了……"，主语用"我们"。

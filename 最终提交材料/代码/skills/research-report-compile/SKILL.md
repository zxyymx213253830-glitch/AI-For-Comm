# 科研汇报统稿（七章节闭环）

## 何时使用

上游多个智能体已各自产出材料（推导、协议分析、Verilog 代码、仿真曲线、文献综述、校验结论），需要一份面向组会/课程答辩的汇总汇报时。

## 统稿四步（按序执行）

1. **【收集】** 接收各智能体的原始产出，登记来源（哪个智能体、哪个版本、对应哪道子问题）
2. **【组织】** 按"问题-方法-结果-结论"结构重组：去重、去寒暄、去冗余；多来源冲突时并列呈现并标注
3. **【成文】** 按下方固定七章节输出
4. **【复核】** 自查每个结论有无对应材料支撑；无来源的论断一律标注"待验证"，不得写成既定结论

## 输出结构（固定七章节）

```
# 科研汇报：{题目}
## 摘要          （≤150 字：问题 + 方法 + 核心结果一句话）
## 1. 研究问题    （背景一句 + 明确的研究问题）
## 2. 方法        （关键公式/协议规范/硬件设计/仿真参数，注明来源智能体）
## 3. 结果        （关键数值、曲线、图表引用，注明来源智能体）
## 4. 结论        （3 条以内，每条对应一个结果）
## 5. 局限与下一步（≤3 条）
## 附录：材料清单 （来源智能体、版本、关键产出摘要）
```

## 硬约束

- 禁止编造数据：各智能体没给出的数值一律不得补写
- 禁止大段复制原始输出不做整理：必须重写为汇报语言
- 校验评级必须保留：若收到【不通过】反馈，修改后重发，不得美化或淡化
- 中文为主，术语保留英文原名（LDPC、URLLC、Polar code 等）
- 图表引用格式"图1：……"，并在材料清单注明原始出处

## 与报告渲染流水线的边界

本技能面向"纯文本汇报稿"场景。结构化研究报告（HTML 渲染、JSON 统稿协议）走主流水线的报告编辑环节，两者勿混用输出协议。

# 信道编码基础

## 别名
Channel coding、纠错编码、Error correction code、ECC、FEC、LDPC、Polar码、Turbo码、卷积码

---

## 一、基本概念

### 1.1 为什么需要编码

AWGN 信道不加编码（BPSK），BER=10⁻⁵ 需要 Eb/N₀ ≈ 9.6 dB。香农极限只需要 -1.59 dB。

```
差距 = 9.6 - (-1.59) = 11.19 dB

这就是编码的进步空间 ↓

有编码：
  LDPC:      距极限 0.1~0.5 dB   → 净赚 10+ dB
  Polar:     距极限 0.3~0.8 dB
  Turbo:     距极限 0.5~1.0 dB
  卷积码:     距极限 2~3 dB
```

### 1.2 编码参数

| 参数 | 符号 | 含义 | 示例 |
|------|------|------|------|
| 信息位长度 | k | 原始信息比特数 | k=1024 |
| 编码后长度 | n | 加入冗余后的比特数 | n=2048 |
| 码率 | R = k/n | 有效信息占比 | R=1/2 |
| 冗余度 | 1-R = (n-k)/n | 用于纠错的比特占比 | 0.5 |
| 最小距离 | d_min | 两个不同码字的最小汉明距离 | d_min=6 |
| 纠错能力 | t = ⌊(d_min-1)/2⌋ | 保证纠正的错误数 | t=2 |

## 二、码的性能度量

### 2.1 编码增益

```
编码增益 (Coding Gain) = 未编码SNR(dB) - 编码后SNR(dB)
                        （在相同 BER 下比较）

实际含义：加了编码后，发射功率可以降低多少 dB
```

### 2.2 香农限距

```
Shannon Gap = 编码方案的 Eb/N₀(实际, BER=10⁻⁵) - 香农极限(-1.59 dB)

Shannon Gap 越小 → 编码越好 → 越接近理论极限
```

## 三、主要编码方案详解

### 3.1 LDPC 码（低密度奇偶校验码）

**历史**：Gallager 1962 发明 → 遗忘 30 年 → MacKay & Neal 1996 重新发现。

#### 3.1.1 Tanner 图与校验矩阵

```
LDPC 码由稀疏校验矩阵 H 定义。每行是一个校验方程，每列是一个变量节点。

Tanner 图 = 二部图：
  变量节点 (n 个) ○───────□ 校验节点 (n-k 个)
                     边 = H 中的"1"

"低密度" → H 中 1 的比例 << 0.5（典型值：每列 3-6 个 1）
```

#### 3.1.2 置信传播 (BP) 解码

```
初始化：从信道 LLR 出发
  L_i^ch = log( P(y_i|x_i=0) / P(y_i|x_i=1) )

迭代：
  1. 变量 → 校验：发送外部信息
  2. 校验 → 变量：发送校验节点更新
  3. 更新变量节点的总 LLR
  4. 硬判决：若 LLR>0 判 0，否则判 1
  5. 用 H 验证：若 H·ĉ = 0 则停止

最多迭代次数通常设为 20-50 次
```

#### 3.1.3 5G NR 中的 LDPC

```
5G NR 数据信道采用准循环 (QC-) LDPC：
  - 两个基图 (BG1/BG2)：BG1 用于高码率大块长，BG2 用于低码率小块长
  - 基图通过循环移位扩展为完整矩阵
  - 支持码率 R ∈ {1/3, 1/2, 2/3, 3/4, 5/6, ...}
  - 支持升/降码率以适应信道变化（速率匹配）
  - 最大块长 ≈ 8000 bit，最小 ≈ 30 bit

HARQ:
  - 首次传输可能不成功 → NACK
  - 重传时发送额外的冗余比特（增量冗余 IR-HARQ）
  - 接收端合并所有接收版本的 LLR
```

### 3.2 Polar 码（极化码）

**历史**：Arıkan 2009 发明——首个被严格证明达到二进制输入对称信道容量的编码方案。

#### 3.2.1 信道极化原理

```
核心发现：

取 N=2ⁿ 个相同的 B-DMC 信道 W，
通过递归的"合并-拆分"操作，
这些信道会极化为两类：

  ┌─ 好信道：容量 → 1 → 无噪传输信息比特
  └─ 坏信道：容量 → 0 → 只能传冻结比特（收发双方约定的固定值）

当 N→∞ 时：
  好信道的比例 → I(W) = C（恰等于原始信道容量！）
  坏信道的比例 → 1 - C

这就是"极化"——信道不是变好就是变坏，没有中间态
```

#### 3.2.2 编码构造

```
编码：x₁^N = u₁^N · G_N

其中 G_N = B_N · F^(⊗n)   （生成矩阵）
      F = [1 0; 1 1]       （极化核）

步骤：
  1. 选 N·C 个最好的比特信道放信息比特
  2. 其余信道放冻结比特（通常全 0）
  3. 用 G_N 编码得到 x₁^N
```

#### 3.2.3 解码算法

| 算法 | 复杂度 | 性能 | 说明 |
|------|--------|------|------|
| **SC (逐次消除)** | O(N·log N) | 一般 | 依次判决 uᵢ，利用已判决比特 |
| **SCL (SC-List)** | O(L·N·log N) | 好 | 保留 L 条候选路径，L=8 通常足够 |
| **CA-SCL (CRC-aided SCL)** | O(L·N·log N) | 很好 | SCL + CRC 校验选最优路径 |
| **BP** | O(N·log N) 迭代 | 中等 | 用 Tanner 图做置信传播 |
| **SC-Flip** | O(N·log N) 平均 | 接近 CA-SCL | 低复杂度替代方案 |

#### 3.2.4 5G NR 中的 Polar 码

```
5G NR 控制信道 (下行 DCI, 上行 UCI) 采用 Polar 码：
  - N_max = 1024 (2^10)
  - 支持码率 R 从 1/8 到 8/9
  - 分布式 CRC (穿插在信息比特之间用于早停)
  - Parity-check Polar (PC-Polar) 改进最小距离
```

### 3.3 Turbo 码

**历史**：Berrou, Glavieux & Thitimajshima 1993 发表，震惊整个通信界——当时最好的码距极限还差 3-4 dB，Turbo 直接做到 1 dB 以内。

#### 3.3.1 结构

```
          ┌──[交织器 Π]──→ [RSC 编码器 2] ──┐
  u ──────┤                                  ├──────→ (u, p₁, p₂)
          └──→ [RSC 编码器 1] ───────────────┘

RSC: 递归系统卷积码 (一个反馈的卷积码)
交织器: 打乱比特顺序，使两个编码器看到的输入"看起来独立"
```

#### 3.3.2 迭代解码

```
两个软输入软输出 (SISO) 解码器交替工作：

迭代 1: 解码器 1 用信道 LLR + 先验 =0 → 产生外部信息
        → 外部信息经解交织 → 作为解码器 2 的先验

迭代 2: 解码器 2 用信道 LLR（经交织） + 先验 → 产生外部信息
        → 外部信息经交织 → 作为解码器 1 的新先验

重复 6-8 次，每次迭代 BER 下降

这就是 "Turbo 原理"——用迭代从噪声中"挖掘"信息
```

#### 3.3.3 应用

| 标准 | 码率范围 |
|------|---------|
| 3G WCDMA | 1/3（约束长 K=4） |
| 4G LTE 数据信道 | 1/3（约束长 K=4, 8 状态） |
| 深空通信 (CCSDS) | 1/2, 1/3, 1/4, 1/6 |

### 3.4 卷积码

**历史**：Elias 1955 发明，Viterbi 1967 提出最优解码算法。

#### 3.4.1 结构

```
编码器是一个有限状态机 (2^K 个状态，K 为约束长度)：

  输入 uᵢ → [移位寄存器 K 级] → [模2加组合] → 输出 vᵢ^(1), vᵢ^(2)

参数：(n=2, k=1, K=7) 是最常用的卷积码之一
  - 每次输入 1 bit，输出 2 bits → R=1/2
  - 7 级移位寄存器 → 64 状态
```

#### 3.4.2 Viterbi 解码

```
在格图 (Trellis) 上做最短路径搜索：

  1. 从状态 0 出发
  2. 对每个时刻，计算各状态分支度量（欧氏距离）
  3. 加累积度量
  4. 每个状态保留最佳路径（幸存路径）
  5. 回溯找到最可能路径 → 输出解码结果

复杂度：O(2^K · L)，K 是约束长度，L 是序列长度
```

## 四、编码方案性能对比

| 编码方案 | Shannon Gap @ BER=10⁻⁵ | 复杂度 | 延迟 | 5G 使用 |
|---------|----------------------|--------|------|---------|
| **LDPC** | 0.1~0.5 dB | O(n) (近似) | 中 | ✅ 数据信道 |
| **Polar (CA-SCL)** | 0.3~0.8 dB | O(L·n·log n) | 低-中 | ✅ 控制信道 |
| **Turbo** | 0.5~1.0 dB | O(n·迭代次数) | 高 | ❌ (4G) |
| **卷积 (Viterbi)** | 2~3 dB | O(2^K·n) | 低 | ❌ (3G) |
| **BCH/RS** | 3~5 dB | O(n²) | 低 | ❌ (传统) |
| **未编码 BPSK** | ~11 dB | — | — | ❌ |

## 六、速率匹配与 HARQ

### 6.1 速率匹配

```
问题：编码块的固定码率不一定匹配物理资源

解决（5G NR 方案）：
  1. 选择一个"母码"，生成固定数量编码比特
  2. 存到一个循环缓冲区 (Circular Buffer)
  3. 按需从缓冲区选比特发送
    - 需要更多比特 → 重复
    - 需要更少比特 → 打孔 (Puncturing) 或缩短 (Shortening)
```

### 6.2 增量冗余 HARQ (IR-HARQ)

```
传输 #1 (初传): 发送编码比特子集 → 解码失败 (NACK)
传输 #2 (重传): 发送不同的编码比特子集 → 合并 LLR → 解码成功！

每次重传带来额外的码率降低 → SNR 增益
```

## 七、例题

### 例题 1（编码增益计算）

未编码 BPSK 在 BER=10⁻⁵ 时需要 Eb/N₀=9.6 dB。使用 LDPC 码后只需 Eb/N₀=3.5 dB。求编码增益。

```
编码增益 = 9.6 - 3.5 = 6.1 dB

解释：加了 LDPC 码后，发射功率可以降低 6.1 dB
      → 功率降低 4 倍（因为 10·log₁₀(4) ≈ 6 dB）
      → 或者覆盖范围扩大约 1.4 倍
```

### 例题 2（码率与 Eb/N₀ 的关系）

若 R=1/2 的编码方案在 Eb/N₀=2 dB 时可靠工作，同样的编码方案在 R=3/4 时需要多少 Eb/N₀？

```
码率越高 → 冗余越少 → 需要更高 Eb/N₀

经验法则（粗略）：
  R↑ 0.25 → Eb/N₀ 需增加约 1-2 dB
  → R=3/4 约需 Eb/N₀ = 2 + 1.5 = 3.5 dB（估）

精确计算需要看具体编码的 BER 曲线
```

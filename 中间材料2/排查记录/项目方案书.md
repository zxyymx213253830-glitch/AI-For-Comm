## 一、项目构想

### 1.1 我们要做什么

打造一个面向**通信领域**的多智能体（Multi-Agent）协作系统。用户提出一个通信相关问题，系统内部多个专业 Agent 像一个真实工程师团队一样分工协作、互相讨论、交叉验证，最终输出经过验证的高质量答案。

系统覆盖三个学科域：

| 领域 | 内容 | 典型问题 |
|------|------|----------|
| 通信工程 | GPPP 协议族、信令流程、信道分析 | "GTPv2 中 Create Session Request 有哪些必选 IE？" |
| 数学理论 | 信息论、信道容量、编码理论、数学建模 | "AWGN 信道 B=20MHz、SNR=30dB，求信道容量" |
| 硬件实践 | FPGA 开发、Verilog/VHDL、时序分析 | "写一个 8B/10B 编码器的 Verilog 模块并说明时序约束" |

### 1.2 核心设计理念：节点化

每个 Agent 是一个**独立节点**，节点内部包含四个功能模块：

```
┌─────────────────────────────────┐
│         Agent 节点               │
│  ┌───────────────────────────┐  │
│  │ 执行手册 System Prompt     │  │  角色定义 · 领域知识 · 行为约束
│  ├───────────────────────────┤  │
│  │ 工具集 Skills              │  │  OpenTrek API · 计算器 · RAG检索
│  ├───────────────────────────┤  │
│  │ 记忆存储 Memory            │  │  对话线程 · 历史消息 · 中间结果
│  ├───────────────────────────┤  │
│  │ 消息接口 Message I/O       │  │  收件箱 · 发件 · 全部写日志
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

节点与节点之间**像人用微信聊天一样**互相发消息：

- 数学理论 Agent 推导完公式，把推导过程发给验证 Agent："这是我的推导，请检查"
- 验证 Agent 检查完毕，回发结果："公式正确，单位换算无误，通过" 或 "第三步单位换算有误，应为..."

### 1.3 三条铁律

1. **全链路日志**：每个节点的每次 API 调用、每段思考、每条收发消息，全部写入结构化日志。哪里出问题一眼定位，整个过程可回放。
2. **测试先行**：先用一道已知标准答案的简单题跑通双节点链路，验证架构通畅后再扩展复杂场景。
3. **Prompt 即配置**：每个 Agent 的执行手册是独立的 Markdown 文件，改行为不改代码，三人可并行编辑。

### 1.4 创新点（答辩要点）

1. **不是单 Agent 问答，而是多 Agent 协作团队**——每个 Agent 有独立身份、记忆和工具
2. **微信式节点通信**——不是硬编码 workflow，Agent 通过消息总线自主收发消息
3. **OpenTrek 平台深度集成**——基于 OpenTrek Agent API 构建每个节点，OpenTrek 知识库提供领域 RAG，协作框架完全自研
4. **SSE 流式实时输出**——利用 OpenTrek 的 SSE 流式接口，思考过程（thought.delta）与回答文本（message.delta）实时分离输出，全过程可观测
5. **跨学科覆盖**——通信工程 × 数学理论 × 硬件实践，一个系统打通通信领域全栈
6. **全链路可追溯**——结构化日志记录每一次 API 调用与思考，OpenTrek 原生 trace 支持（trace=true），支持回放与调试
7. **平台原生记忆与知识库高级检索**——OpenTrek 支持 memoryUserId 实现用户级记忆隔离，知识库 API 支持 AND/OR 复合逻辑过滤与元数据检索

### 2.1 节点间消息格式

```json
{
  "from": "math_agent",
  "to": "verify_agent",
  "type": "derivation",
  "content": "信道容量推导过程：C = B·log₂(1+S/N) ...",
  "timestamp": "2026-07-22T16:30:00"
}
```

消息类型约定：`question`（提问）、`derivation`（推导/结果）、`feedback`（验证反馈）、`request`（请求协助）。

### 2.2 解题工作流

```
1 接收问题 → 2 任务分解 → 3 Agent 求解 → 4 交叉验证 → 输出答案
```

以信道容量题为例的完整消息流：

1. 用户输入 → Orchestrator 识别为信息论问题
2. Orchestrator → math_agent："请计算信道容量"
3. math_agent 调用 OpenTrek API 推导 → 得出 199.5 Mbps
4. math_agent → verify_agent（derivation 消息）
5. verify_agent 复核公式与数值 → 回发 feedback（通过）
6. Orchestrator 聚合结果 → 输出给用户
7. 全过程 6 条日志落盘

### 3.0 OpenTrek API 调用流程

本项目采用以下 OpenTrek 接口（API 文档见项目根目录 PDF）：

| 步骤 | 接口 | 作用 | 关键参数 |
|------|------|------|----------|
| 1 | createSession | 创建 Agent 会话 | agentCode, agentVersion → 返回 uniqueCode (sessionId) |
| 2 | /run | 发起对话并获取回答 | sessionId, stream=true, delta=true, message.text |
| 3 | 知识库检索 (kortex) | RAG 检索领域知识 | kbIndexCode, query, x-sfm-workspacecode |

完整调用链路：`createSession → /run(SSE) → 解析 thought.delta + message.delta → 返回回答`

> **备选流程**（复杂多 Agent 场景）：`createSession → createNewChannel(SSE) → /auto/new/open/run(异步) → 通过 SSE 通道接收结果`。本项目当前采用简单流程（步骤 1+2），多 Agent 协作通过本地 MessageBus 实现节点间消息传递。

### 3.3 核心代码：Agent 节点（A 实现）

```python
# core/agent_node.py
import json, urllib.request, urllib.error
from datetime import datetime
from core.config import OPENTREK_BASE_URL, APP_KEY, REQUEST_TIMEOUT, SSE_READ_TIMEOUT
from core.logger import log

class AgentNode:
    """一个 Agent 节点 = OpenTrek 控制台已创建的 Agent + 独立 Session + 收件箱"""

    def __init__(self, name: str, agent_code: str, agent_version: str, bus=None):
        self.name = name
        self.agent_code = agent_code        # OpenTrek 智能体编码 (UUID)
        self.agent_version = agent_version   # OpenTrek 版本编码
        self.bus = bus
        self.inbox = []
        # 创建专属会话
        self.session_id = self._create_session()
        if self.bus:
            self.bus.register(name)
        log.info("agent.init", agent=name, session_id=self.session_id)

    def _request(self, path, body, timeout=REQUEST_TIMEOUT):
        """向 OpenTrek 发送 POST，返回 JSON"""
        url = f"{OPENTREK_BASE_URL}/{path}"
        data = json.dumps(body, ensure_ascii=False).encode("utf-8")
        req = urllib.request.Request(url, data=data, headers={
            "Authorization": f"Bearer {APP_KEY}",
            "Content-Type": "application/json",
        }, method="POST")
        with urllib.request.urlopen(req, timeout=timeout) as resp:
            return json.loads(resp.read().decode("utf-8"))

    def _create_session(self) -> str:
        """创建会话，返回 uniqueCode（即 sessionId）"""
        resp = self._request("createSession", {
            "agentCode": self.agent_code,
            "agentVersion": self.agent_version,
        })
        if not resp.get("success"):
            raise RuntimeError(f"createSession 失败: {resp}")
        return resp["data"]["uniqueCode"]

    def think(self, task: str) -> str:
        """把任务发给 OpenTrek Agent（SSE 流式），返回完整回复"""
        log.info("agent.think.start", agent=self.name, task=task[:100])
        url = f"{OPENTREK_BASE_URL}/run"
        body = json.dumps({
            "sessionId": self.session_id,
            "stream": True, "delta": True,
            "message": {"text": task, "metadata": {}, "attachments": []},
        }, ensure_ascii=False).encode()
        req = urllib.request.Request(url, data=body, headers={
            "Authorization": f"Bearer {APP_KEY}",
            "Content-Type": "application/json",
        }, method="POST")
        with urllib.request.urlopen(req, timeout=SSE_READ_TIMEOUT) as resp:
            text = self._parse_sse(resp)
        log.info("agent.think.done", agent=self.name, reply=text[:100])
        return text

    @staticmethod
    def _parse_sse(resp) -> str:
        """解析 SSE 流：thought.delta（思考过程，忽略）+ message.delta（回答，累计）"""
        parts, buf = [], ""
        while True:
            chunk = resp.read(8192)
            if not chunk:
                break
            buf += chunk.decode("utf-8", errors="replace")
            lines = buf.split("\n"); buf = lines.pop()
            for line in lines:
                line = line.strip()
                if not line.startswith("data:"):
                    continue
                js = line[5:].strip()
                if js == "[DONE]":
                    return "".join(parts)
                try:
                    obj = json.loads(js)
                except json.JSONDecodeError:
                    continue
                t = obj.get("object", "")
                c = obj.get("content", {})
                if t == "message.delta" and isinstance(c, list) and c:
                    ti = c[0].get("text", {})
                    if isinstance(ti, dict):
                        parts.append(ti.get("value", ""))
                elif t == "text.delta" and isinstance(c, dict):
                    parts.append(c.get("data", ""))
                elif t == "complete":
                    return "".join(parts)
        return "".join(parts)

    def send(self, to_agent: "AgentNode", msg_type: str, content: str):
        """向另一个节点发消息（微信式）"""
        msg = {
            "from": self.name, "to": to_agent.name,
            "type": msg_type, "content": content,
            "timestamp": datetime.now().isoformat(),
        }
        to_agent.inbox.append(msg)
        log.info("agent.message", **{k: (v[:80] if k == "content" else v) for k, v in msg.items()})
        return msg
```

> **OpenTrek SSE 流式特性**：每次 `/run` 调用返回 SSE 流，包含 `thought.delta`（AI 思考过程增量）和 `message.delta`（最终回答文本增量）。思考过程可用于调试和日志展示，回答文本拼接后输出给用户。

```python
# core/message_bus.py
from collections import defaultdict
from core.logger import log

class MessageBus:
    """发布/订阅总线：节点注册邮箱，消息按收件人路由"""
    def __init__(self):
        self._mailboxes = defaultdict(list)

    def register(self, agent_name: str):
        self._mailboxes[agent_name] = []

    def post(self, msg: dict):
        self._mailboxes[msg["to"]].append(msg)
        log.info("bus.post", sender=msg["from"], receiver=msg["to"], type=msg["type"])

    def fetch(self, agent_name: str) -> list:
        msgs, self._mailboxes[agent_name] = self._mailboxes[agent_name], []
        return msgs
```

### 3.5 OpenTrek 知识库操作：RAG 搭建（C 实现）

在 OpenTrek 控制台创建 3 个知识库，通过 kortex API 检索：

| 知识库 | 上传内容 | 检索字段 |
|--------|----------|----------|
| 通信协议库 | 3GPP TS 29.274 (GTPv2)、TS 36.413 (S1AP)、TS 38.413 (NGAP) 等 PDF | text |
| 信息论数学库 | 香农原著章节、Cover《信息论基础》公式集、典型例题 | text（含公式） |
| FPGA 硬件库 | Verilog 模块模板、时序约束指南、Xilinx/Altera 文档 | text |

**操作步骤（约 10 分钟/个）：**

1. OpenTrek 控制台 → 知识库管理 → 创建知识库 → 本地上传 PDF/DOCX/MD
2. 记录每个知识库的 `kbIndexCode`（检索时必填）
3. 记录 `workspacecode`（检索请求头 `x-sfm-workspacecode` 必填）
4. 调用检索接口验证命中质量：

```python
# 知识库检索验证（core/kb_client.py）
import json, urllib.request

KB_URL = "http://<platform-host>:80/sfm-agent-studio/sfm-api-gateway/gateway/kortex/api/kb/mono/retrieve"
APP_KEY = "your_app_key"
WORKSPACE = "your_workspace_code"

def kb_retrieve(query, kb_index_code, field_name="text", score=0.01, limit=10):
    """OpenTrek 知识库通用检索"""
    req = urllib.request.Request(KB_URL, data=json.dumps({
        "kbIndexCode": kb_index_code,
        "kbIndexRetrieveFieldName": field_name,
        "query": query,
        "score": score,
        "limit": limit,
    }).encode(), headers={
        "Authorization": f"Bearer {APP_KEY}",
        "x-sfm-workspacecode": WORKSPACE,
        "Content-Type": "application/json",
    }, method="POST")
    with urllib.request.urlopen(req, timeout=30) as resp:
        return json.loads(resp.read().decode())

# 命中测试
result = kb_retrieve("GTPv2 Create Session Request 必选IE", "your_kb_index_code")
for item in result.get("data", []):
    print(f"[score={item.get('score'):.2f}] {item.get('text', '')[:80]}")
```

> **高级检索能力**：OpenTrek 知识库 API 支持 `advancedRules` 复合逻辑过滤（AND/OR），可按 `fileName`、字段名进行 EQ（等于）、IN（包含）、IS_NOT_NULL（非空）、LIKE（模糊匹配）等条件组合检索，适用于精确定位特定协议文档或公式章节。

### 3.7 第一个测试用例（架构验证，第 3 天必须跑通）

**题目**：AWGN 信道，带宽 B = 20MHz，信噪比 SNR = 30dB，求信道容量。

**标准答案**（C 负责核对）：

```
SNR 线性值 = 10^(30/10) = 1000
C = B · log₂(1 + SNR) = 20×10⁶ × log₂(1001) ≈ 199.5 Mbps
```

**验证清单**：
- [ ] math_agent 正确调用香农公式
- [ ] dB → 线性值换算正确（10^3 = 1000）
- [ ] math_agent 主动向 verify_agent 发送 derivation 消息
- [ ] verify_agent 回发 feedback 消息
- [ ] logs/session.jsonl 中出现完整的消息流记录

**进阶测试**（知识库接入后）：
- GTPv2 Create Session Request 必选 IE 有哪些？Cause=73 什么含义？（验证 RAG 检索与规范引用）

## 六、风险与对策

| 风险 | 概率 | 对策 |
|------|------|------|
| OpenTrek API 行为与预期不符（SSE 解析异常等） | 中 | Day 1 先用 createSession + /run 跑最小验证；备选方案改为非流式 stream=false 直接获取完整 JSON |
| 知识库检索命中率低 | 中 | 文档切分调优；advancedRules 按文档名过滤精准定位；必要时改为全文注入 |
| 多 Agent 对话死循环 | 低 | Orchestrator 设最大轮次（如 8 轮）强制收敛 |
| OpenTrek 平台内网访问受限 | 低 | 统一在校园网/VPN 环境下开发；APP_KEY 妥善保管 |
| SSE 流式响应中断或超时 | 低 | 设置 SSE_READ_TIMEOUT=300s；解析器有 MAX_LINES 保护；失败自动重试 |

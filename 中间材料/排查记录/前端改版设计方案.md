# AI for Comm 项目介绍与前端功能需求

> 本文档用于向设计师完整介绍本项目：项目是什么、核心业务如何运转、
> 新版前端需要承载哪些功能。文档只描述产品与功能，
> 视觉风格完全交由设计师自由发挥。

---

## 一、项目介绍

### 1.1 项目定位

**AI for Comm（通信科研多智能体平台）** 是一个面向通信领域科研场景的多智能体协作平台。
用户提出一个通信领域的研究问题（例如「BPSK 在 AWGN 信道下的误码率理论推导与仿真验证」），
平台自动调度七位专家智能体分工协作，完成从问题拆解、文献调研、理论推导、协议分析、
代码仿真、硬件设计到最终研究报告生成的全流程科研工作。

**一句话概括：给一个科研问题，平台自动产出一份经过校验的完整研究报告。**

### 1.2 目标用户与使用场景

| 用户类型 | 典型场景 |
| --- | --- |
| 通信专业学生 | 课程作业中的公式推导、仿真验证、文献综述 |
| 科研工作者 | 课题调研、理论对照仿真、快速验证想法 |
| 竞赛参赛团队 | 短时间内产出结构完整的研究报告（本项目服务于 AI 创新大赛） |

### 1.3 两种使用模式

- **快问快答**：用户提一个小问题，平台自动路由到最合适的一位专家即时回答。用户无需知道背后是哪位专家，平台自动判断。
- **科研任务**：用户提交一个完整课题，平台启动六步全自动流水线，最终产出可下载、可在线查看的研究报告。

### 1.4 系统架构

平台采用「本地编排器 + 云端智能体」的两层架构：

```
用户浏览器（前端）
    │
本地编排器 —— 负责调度、消息总线、仿真执行、报告渲染
    │
OpenTrek 智能体平台（云端）—— 托管七位专家智能体
```

**七位专家智能体：**

| 智能体 | 职责 |
| --- | --- |
| 数学推导 Agent | 信息论公式推导、信道容量计算 |
| 通信工程 Agent | 3GPP 协议查询、信令流程分析 |
| 硬件实践 Agent | FPGA / Verilog 模块生成、时序分析 |
| 通信仿真 Agent | 蒙特卡洛仿真代码生成与运行（误码率曲线、星座图等） |
| 文献调研 Agent | 公网 + 平台知识库双源检索与综述 |
| 验证 Agent | 对其他专家产出做三级校验：通过 / 有条件通过 / 不通过 |
| 报告主编 Agent | 把各专家产出统稿成结构化研究报告 |

**协作机制**：各智能体通过消息总线异步通信；任务完成后必须提交验证 Agent 校验，
不通过则修正后重新提交，形成「生成 → 校验 → 修正」闭环。

### 1.5 科研任务六步流水线

1. **问题拆解** —— 把课题拆成子任务，分发给各领域专家
2. **文献调研** —— 双源检索并生成文献综述
3. **并行专家** —— 数学 / 通信 / 硬件 / 仿真四位专家并行工作
4. **综合校验** —— 验证 Agent 逐项审查，不通过则打回修正（最多两轮）
5. **报告统稿** —— 报告主编把各部分整合成结构化内容
6. **报告渲染** —— 排版成最终的研究报告

### 1.6 内容形态（页面中会出现的数据类型）

设计师需要了解平台输出内容的构成，以便规划信息承载方式：

- 数学公式（如香农信道容量公式、误码率表达式）
- 代码块（Python 仿真代码、Verilog 硬件描述代码）
- 图表（误码率曲线、星座图等仿真结果图片）
- 文献条目（标题、作者、年份、摘要）
- 结构化研究报告（含目录、章节、图表混排）
- 实时运行日志（每条日志标注来源智能体）

### 1.7 关键体验特征

1. **流式输出**：所有回答逐字流式返回，单条回答时长可达数十秒到数分钟。
2. **长任务等待**：完整科研流水线耗时较长（分钟级），用户需要看得见进度。
3. **过程透明**：多智能体协作的过程本身是产品的核心亮点，应当呈现给用户。

## 二、现有前端现状与痛点

### 2.1 现有页面（共四页）

| 页面 | 当前功能 |
| --- | --- |
| 对话问答 | 聊天界面，单一消息流，自动路由专家 |
| 科研任务 | 课题输入框 + 六步横向进度条 + 运行日志 |
| 报告库 | 历史报告卡片（文件名 / 时间 / 大小，在线查看与下载） |
| 设置 | 平台接入配置 + Agent 注册表 |

### 2.2 现有痛点（新版要解决的问题）

1. **流水线过程不可见**：进度条过于简单，看不出哪个智能体正在工作、产出了什么。
2. **聊天页价值感弱**：无法体现「背后有多位专家」，本次由哪位专家回答也不展示。
3. **报告库无检索无预览**：只有文件名，没有摘要与搜索筛选。
4. **缺少智能体总览视图**：智能体在线状态、知识库绑定情况只在设置页以表格呈现，不直观。
5. **异常状态缺失**：任务失败、平台断连等场景没有处理。

## 三、功能需求方案（新版前端）

### 3.1 整体布局

- **左侧固定导航栏**：品牌区（Logo + 平台名）、主导航、底部平台连接状态指示。
- **顶部栏**：当前页面标题 + 全局状态（平台连接状态、运行中任务数）。
- **主内容区**：以 1280px 以上桌面端为主，1024px 可用。

主导航五项：对话问答、科研任务、报告库、智能体监控（新增）、设置。

### 3.2 页面功能需求

#### 页面一：对话问答（首页）

核心目标：让「自动路由专家」被用户看见。

功能需求：
- 首次进入为欢迎态：品牌标语 + 六张专家能力卡片（数学推导 / 协议分析 / 硬件实践 / 通信仿真 / 文献调研 / 综合校验），点击卡片直接填入示例问题。
- 输入区：多行输入框，回车发送 / Shift+回车换行，附常用问题快捷标签。
- 消息流：用户消息与系统回答分列；每条回答展示「路由徽章」——标明本次由哪位专家回答。
- 流式打字效果，以及回答生成中的等待状态（标明正在由哪位专家处理）。
- 富内容渲染：数学公式、代码块（带语言标签和复制按钮）、图表图片。

需覆盖的状态：欢迎态、流式输出中、回答完成、路由失败提示、平台断连提示。

#### 页面二：科研任务（核心页面）

核心目标：完整呈现六步流水线的执行过程。

功能需求：
- 课题输入区：大输入框 + 示例课题标签（一键填入）+「开始研究」按钮。
- 流水线可视化，需呈现：当前执行到第几步、当前由哪位智能体在工作、每步的耗时与产出摘要。
- 实时日志面板：日志流按来源智能体区分标识。
- 阶段产出预览：每个阶段完成后可展开查看产出摘要（如拆解出的子任务列表、检索到的文献条目）。
- 校验环节：验证不通过时显示「打回修正」状态（含第几轮修正），通过时给出明确的通过标记。
- 完成态：结果横幅 + 报告预览入口 + 前往报告库的引导。

需覆盖的状态：待启动、执行中、校验打回、执行失败、执行成功。

#### 页面三：报告库

核心目标：集中管理历次科研任务产出的研究报告。

功能需求：
- 报告卡片网格：报告标题、生成时间、大小、参与智能体标识。
- 顶部搜索框 + 时间排序。
- 卡片操作：在线查看（新标签打开报告页）、下载。
- 空状态：无报告时引导用户去科研任务页发起第一个课题。
- 报告在线查看页：目录侧栏、章节锚点、公式与图表混排的阅读布局。

#### 页面四：智能体监控（新增页面）

核心目标：总览七位智能体的实时健康状况。

功能需求：
- 七张智能体卡片：名称、职责一句话、在线 / 离线状态、绑定的知识库数量与名称。
- 汇总统计：在线智能体数、累计完成任务数等。

#### 页面五：设置

核心目标：管理平台接入参数与智能体注册信息。

功能需求：
- 分组表单：「平台接入」（地址、密钥、超时参数）与「Agent 注册表」（表格：名称 / 描述 / 版本 / 知识库 / 在线状态）。
- 保存 / 重载操作与保存结果反馈。
- 敏感字段（密钥）遮蔽式输入。

### 3.3 通用组件清单

导航侧栏、顶部栏、按钮（主要 / 次要 / 危险，含悬停 / 按下 / 禁用 / 加载态）、
输入框与表单、卡片、徽章标签（智能体身份、状态、阶段）、步骤进度呈现、
消息气泡（用户 / 系统 / 各专家）、日志行、轻提示、空状态、加载骨架屏、
错误与断连提示、智能体节点（在线 / 工作中 / 离线三态）。

## 四、技术约束提醒

1. 前端为服务端渲染模板 + 原生 JS，无大型前端框架。
2. 数学公式、代码高亮已有成熟渲染方案，页面中预留渲染区域即可。
3. 页面文案全部为中文，设计稿中的占位文案请使用中文真实语境（可用本文档中的示例课题）。
4. 平台部署在内网演示环境，外部字体 / 图片资源需可离线或打包内置。
